## Chaos drill: what each scenario means for this source

How to run the drill: [docs/runbooks/chaos-drill.md](../chaos-drill.md). What each scenario means here:

| Scenario | Detects | Code | Severity | Alert | Retryable |
|---|---|---|---|---|---|
| late | the file completes this source's expected set after the custodian's cutoff | `-` | info | custodian_late_arrival | no |
| malformed | No record type of the spec matches the line. | `RECORD_TYPE_UNKNOWN` | error | chaos_scenario | yes |
| duplicate | Two records in the file carry the same key, so the merge cannot tell which is current. | `MERGE_DUPLICATE_KEY` | error | chaos_scenario | yes |
| truncated | trailer record count equals the number of detail records | `trailer_control_total` | error | chaos_scenario | yes |

Resolution, per scenario:

- **late**: Nothing to fix: the file's own content is correct, only its arrival was late. The scenario ends once the custodian_late_arrival alert is confirmed.
- **malformed**: Compare the line with the spec; a new record type needs a spec version.
- **duplicate**: Ask the custodian which record is right; both are held back.
- **truncated**: Ask the custodian to resend a complete file; the trailer's own count no longer matches the file's detail records.
